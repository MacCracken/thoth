# thoth — P(-1) hardening audit, 2026-08-24 (0.39.0)

Scope: thoth's **authored** source only — `src/*.cyr` + `src/gui/*.cyr`, ~19,500 lines across 40 files.
`lib/` (the vendored Cyrius stdlib snapshot) and `src/vendor/**` (the vendored dist bundles) were read to
understand contracts but are upstream, and defects there are not thoth findings.

Method: six parallel auditors, one per dimension (buffer/pointer safety · allocation-failure and unchecked
returns · command injection, path traversal and the tool jail · parsing untrusted wire data · secret
handling · state-machine and resource correctness), each finding then handed to an **independent skeptic
briefed to refute it**. 26 findings filed, **17 confirmed, 1 refuted**, several duplicates across
dimensions. Two findings were reproduced by the verifiers as live crashes rather than argued on paper.
Two more (A-1, A-2) were found by hand before the sweep reported.

**All 11 distinct issues are fixed in 0.39.0.** Every fix carries a regression test; where a test could
not genuinely distinguish the pre-fix behaviour, that is stated rather than glossed.

Severity: CRITICAL (remote/privilege escalation) · HIGH (moderate effort) · MEDIUM (specific conditions) ·
LOW (defense-in-depth), per the
[first-party standards](https://github.com/MacCracken/agnosticos/blob/main/docs/development/first-party/first-party-standards.md#security-hardening-required-before-every-release).

---

## The theme

Nine of the eleven sit on one seam: **thoth's boundary between itself and the untrusted party it hosts.**
The model is not trusted, the repository is not trusted, the gateway's JSON is not trusted, and a filename
is not trusted. thoth's design already knows this — the jail, the t-ron gate, the deny-biased layering in
`shell.cyr` are all evidence of it — and the failures were not missing intent but **premises that had gone
stale, and boundaries applied at one sink but not its sibling**.

Two findings deserve singling out because they are the same mistake in different clothes:

- The jail's symlink hole (**A-1**) was *documented as accepted*, in two files and an ADR, on the grounds
  that there was "no portable `O_NOFOLLOW`". That premise was true when written and false by the time it
  was relied on: `lib/fs.cyr` ships a portable `is_symlink`. **A documented residual is a claim with an
  expiry date, and nothing was re-checking it.**
- `led_paste` had already established the correct policy for terminal-escape bytes in 0.17.0 — and the two
  *other* paths that ingest untrusted bytes into the same composer and the same terminal (**A-7/A-8**) never
  adopted it. The right fix was not a third filter but moving the existing one to where the bytes enter.

## Confirmed findings

### A-1 · HIGH · Symlink escape from the project jail — read **and** write
`src/project.cyr`, `src/edit.cyr`

The jail was purely **lexical**: it refused `/`, `~` and `..`, and nothing else. A path that is lexically
clean but resolves through a **symlink** left the project entirely. Both files documented this as an
accepted residual on the "no portable `O_NOFOLLOW`" premise.

Demonstrated, not theorised: with `_jailprobe -> /etc` in the project,
`read_file {"path":"_jailprobe/hostname"}` returned `archaemenid` — the real contents of `/etc/hostname` —
with the jail reporting the path as safe. The write side was worse: `edit`/`create_file` took the same
lexical check, so a link could redirect a write anywhere the user can write.

Reachability is not exotic. The attacker needs **no shell** — only a symlink in a repository the user opens
thoth in, which a `git clone` will faithfully reproduce.

**Fix**: `_project_no_symlink` walks *every* component (not just the last — `link/sub/file` escapes through
`link`) via the stdlib's portable `is_symlink`, applied at all four tool boundaries. The pure lexical
predicates stay pure; the I/O check sits where I/O already happens. Fails closed on OOM and on an
over-long path.
**Residual, now stated**: `is_symlink` returns 0 on Windows, so the check is a no-op there — the PE lane
must not ship without revisiting it.

### A-2 · MEDIUM · Shell capture file world-readable in `/tmp`
`src/exec.cyr:194`

The capture temp file was created `0644` in world-writable `/tmp`, holding the **full merged stdout+stderr
of a command the model chose to run**. On a shared host any local user could read whatever it printed —
`env`, a token in a build log, `cat ~/.aws/credentials` — for the file's lifetime.

`O_CREAT|O_EXCL` was already correct and *does* defeat a pre-planted file or symlink; `O_NOFOLLOW` was
never the load-bearing flag here, and the header now says so. The mode was simply too generous: thoth opens
the fd itself and `dup2`s it into the child, so nothing outside the process needs to open the path by name.

**Fix**: mode `0600`. **Test**: asserted end-to-end on the real file — the child's stdout *is* that fd, so it
stats itself (`stat -L -c %a /proc/self/fd/1`); skips honestly where `stat -c`/`/proc` are absent.

### A-3 · HIGH · Confused deputy — thoth's own config was inside the model's jail
`src/project.cyr`, `src/edit.cyr`

`.thoth/config.cyml` lives at the repo root, which is where thoth is launched, so it sat inside the jail as
an ordinary relative file. `read_file` carries **no t-ron gate** by design (the jail is its only boundary,
being read-only and project-confined) and `[hoosh].tools` defaults on.

Demonstrated: `read_file {"path":".thoth/config.cyml"}` returned
`token = "SUPERSECRET-AUDIT-CANARY-0039"` — thoth handing the model its own gateway bearer token, which a
prompt-injected model can exfiltrate through `web_fetch` or `shell`.

The write side was worse still: the same path passed the *write* jail, so an `edit` could repoint
`[hoosh].url` at an attacker host or flip `[shell].enabled`, and `/reload` makes it live — **thoth's own
security config, rewritable by the party it constrains**.

**Fix**: `_project_sensitive` refuses `.thoth/` and the legacy `thoth.cyml` at any depth, component-wise
(so `.thothrc` and `my.thoth.bak` are *not* false positives, and the absolute form under a granted read
root is covered), wired into all four tools. The **human** is unaffected — `/read` and `@file` do not go
through this jail.
**Explicitly not a general secret filter**: a project's own `.env` or tokenised `.git/config` remains
readable. That is the operator's project and seeing it is the jail's purpose; redacting it is a different
capability (output filtering) and is tracked as such rather than faked.

### A-4 · MEDIUM · Null-deref on a non-string JSON value — reproduced SIGSEGV
`src/hoosh.cyr` ×2, `src/daimon.cyr` ×1

`if (id != 0)` proves the **key** exists, not that its **value** is a string. `bayan_json_v_str` answers 0
for any non-`JTAG_STR` tag, and `str_data`/`str_len`/`str_eq_cstr` then dereference 0.

A verifier reproduced the crash in a standalone program: body `{"object":"list","data":[{"id":123}]}` →
`exit 139`. This is wire data from a gateway relaying some provider's catalog, so a numeric id is a
plausible upstream shape. The `daimon.cyr` instance is worse in kind: a **third-party MCP server** controls
its own `name`/`description`, making the malformed value attacker-reachable rather than merely unlucky.

29 of the 32 `bayan_json_v_str` call sites already checked correctly — these three were the outliers.
**Fix**: check the `Str` before use at all three; skip the malformed entry and keep rendering.

### A-5 · HIGH · Unbounded creeping write past the citations arena
`src/memory.cyr:187`

`_cite_copy` clamped `avail` to 0 but still wrote `store8(dst + len, 0)` and still advanced
`_cite_off = _cite_off + len + 1`. Once the arena filled **exactly**, the NUL landed at index
`CITE_BUF_CAP` — one past the end — and because `_cite_off` kept advancing, the next call wrote at +1, the
next at +2: an **unbounded** creeping NUL-write into the bump heap, one byte per call, corrupting whatever
was allocated after the arena. Reachable from mneme search results, whose titles and paths the model itself
authors via `/remember`.

**Fix**: a hard bound, not a clamp — if there is no room for even the terminator, write nothing and do not
advance; return a stable empty cstr. **Test**: 200 copies past exhaustion, pinning that `_cite_off` never
passes the cap and that an exhausted arena yields a usable empty string.

### A-6 · HIGH · Heap OOB write **and** heap disclosure on the wire
`src/hoosh.cyr` ×4, `src/agent.cyr` ×1

Every request builder funnels strings through bounded appenders — and those stop with `off` at **exactly**
`cap - 1` when they saturate. `_append_int` then took no cap and wrote unconditionally, so the
`"max_tokens":<n>` append that follows put four digits at `cap-1 … cap+2`: a heap out-of-bounds **write**
past the request buffer.

The second half is worse than the first. The returned length was likewise past the end, and it goes
straight to `sandhi_http_post(..., len)` as the POST body length — so the request **transmitted three bytes
of adjacent heap to the gateway**. One missing bound produced both an OOB write and an information
disclosure.

No hostile gateway required: a large enough user prompt saturates the buffer. A verifier reproduced it by
piping ~50,000 `0x01` bytes (each escaping to a 6-byte ``) into `thoth -p`.

**Fix**: `_append_int_cap`, the bounded twin, using the identical `off < (cap - 1)` guard as
`_append_cstr_cap`; all five builders switched; every terminator clamped so the **returned length can never
name a byte outside the allocation**.
**Test**: a 16-byte canary at the first byte past the cap — deliberately at the boundary, because the
overflow is only 3–4 bytes wide and a canary placed further out would have sat there intact and proved
nothing. **Verified by reverting the fix**: the test produces three failures, then passes again when
restored.

### A-7 / A-8 · HIGH · Terminal-escape injection from filenames
`src/ftree.cyr` (fixing both `src/tui.cyr:1668` and `src/tui.cyr:420`)

A filename is untrusted input — an attacker who can land a file in the tree (a cloned repo, a package, an
archive) controls those bytes. Two sinks consumed them raw:

1. The file-tree pane writes the name to the terminal through `emit_raw_n`, and `feed_clip` **copies an
   unrecognised escape verbatim** — it must, because it carries thoth's own role markers for prose —
   suppressing only a CSI erase-line. So `ESC[2J` in a filename could clear the user's screen, and cursor
   positioning could forge output above it.
2. `@`-Tab completion inserted the same raw bytes into the composer — bypassing the filter `led_paste`
   already applies, whose own comment says a paste "can NEVER inject a terminal escape sequence".

**Fix at the source, not the sinks**: `_tree_set_name` is the single chokepoint where filesystem bytes
enter thoth's tree model. Sanitising there fixes both sinks at once and leaves `feed_clip` free to keep
passing thoth's *own* markers — which is the distinction that matters: escapes thoth generates are trusted,
bytes the filesystem hands us are not. C0 controls and DEL become `?` (width-preserving, and visibly odd
rather than silently rewritten); UTF-8 passes untouched.
**Known, deliberate**: a file whose real name contains a control byte is displayed and opened under its
sanitised spelling, so it is unreachable *via the tree pane*. `/read` with an explicit path still reaches
it.

### A-9 · MEDIUM · Unbounded environment copy smashes the Wayland connect frame
`src/gui/gwindow.cyr`

`gwl_wl__copy_cstr` took no cap. Its sources are `getenv("WAYLAND_DISPLAY")` and
`getenv("XDG_RUNTIME_DIR")`; its destination is `gwl_wl_connect`'s `var path[128]`. A long value smashed
the stack frame — saved registers and return address included — on the *first* call of `gwl_win_open`. A
second, independent overflow followed in the `var addr[120]` sockaddr fill, which had no length check of
its own and no awareness that `sun_path` is only 108 bytes.

Reproduced on the shipping binary: `WAYLAND_DISPLAY=/<200 A's> thoth gui` → `exit 139`; the 118–199-byte
band corrupts the frame silently *without* crashing. A control with an unrelated 5,000-byte env var exits
cleanly, ruling out the stdlib's `getenv` and pinning the fault here.

Severity is bounded by the channel — the environment is thoth's own, the binary is not setuid, and no
model, tool, MCP or network path reaches this buffer — so it is a crash and robustness bug, not a privilege
boundary. The auditor rated it HIGH; the verifier corrected it to MEDIUM and **that correction is
accepted**.

**Fix**: a `cap` parameter returning -1 on overflow, bounded by the smaller of the buffer and `sun_path`'s
real 107-byte capacity, with the caller degrading through its existing "no Wayland compositor" path.
**Verified**: all three previously-crashing invocations now exit 255 (the honest degrade), control
unchanged.

### A-10 · MEDIUM · JSON injection through model-controlled tool arguments
`src/daimon.cyr:71`

`args_json` is the model's `function.arguments`, spliced in **raw** to preserve whatever shape the gateway
forwarded. Raw splicing of untrusted text into a JSON document thoth is itself authoring is an injection
seam: `{}, "name":"other_tool"` closes the arguments object and appends a **second** `name` key, and a
last-key-wins parser on the far side would dispatch a tool t-ron never gated — because thoth authorizes
`name` *before* this point. That is an authorize-one-thing / do-another shape.

**Fix**: validate that the text is exactly one well-formed JSON value before splicing; anything else
degrades to `{}` — the same substitution a null already took — which the agent loop surfaces to the model
as an ordinary tool error.

### A-11 · MEDIUM · The GUI hung forever on a confirm it cannot render
`src/gate.cyr` (fixing `src/gui/gpresent.cyr:167`)

The T3 GUI wraps its turn in `OUT_NULL` because the window, not the terminal, is its output surface. So the
fail-closed confirm's prompt was **discarded**, and `read_line` then blocked on stdin nobody is typing
into. The GUI has no modal to render the prompt in and no path from evdev to `read_line`, so any gated tool
call with no `[tron].policy` — **the default** — hung the turn forever, presenting as a frozen window with
no visible cause.

**Fix**: `confirm` now denies on `OUT_NULL`, on exactly the reasoning the one-shot branch above it already
used — an unanswerable prompt must fail closed rather than deadlock. `OUT_RING` (the T2 TUI) is
deliberately *not* caught: it has hooks that bracket back to the live screen so the prompt **is** visible
there.
**Honest test limit**: the assertion pins the outcome, not the fix — on a runner whose stdin is at EOF the
old code also returned 0. It guards a future regression; the hang only manifests against a stdin that stays
open, which is not reproducible in-process.

**`src/agent.cyr:493` — "streaming tool-call assembly still drops OBJECT-shaped `arguments`"**, filed as a

a refuted finding is evidence the adversarial pass is doing its job, not noise to hide.

## Verified clean (negative results worth recording)

Absence of a finding is only meaningful if someone looked. These were checked and are **sound**:

- **The bearer token has exactly one use site.** `config_hoosh_token` is read only by
  `_hoosh_auth_header`, which builds `Bearer <token>` into a buffer sized *exactly* right
  (`strlen(tok) + 8` for `"Bearer "` + token + NUL). It never reaches a log, `/state`, `/dry`, an export,
  or an error path. Only the HTTP layer sees it.
- **The config-derived buffer class is clean.** thoth has a documented recurring bug where a buffer sized
  from config is not re-allocated when `/reload` changes the value (fixed once in `shell.cyr` at 0.37.0).
  Of the four config getters returning sizes, only `config_shell_output_cap` feeds a buffer, and it goes
  through the fixed `_shell_bufs_ensure`.
- **The shell deny/allow filter is honestly framed.** Its header states it "is a COARSE convenience
  pre-filter, NOT a sandbox: a shell can cd / chain / base64-decode around a string glob… Never claimed
  otherwise." A string denylist over a shell command *is* trivially bypassable — but it is not presented as
  a boundary, so this is documentation doing its job, not security theatre. The absence of a real sandbox
  is a **capability gap**, tracked in the improvements review, not an audit finding.
- **`_project_no_dotdot` does not read past the NUL.** The header's caution about reading past it is
  over-cautious: every access is at or before the terminator.
- **`cyrius vet`** — 57 deps, 0 untrusted, 0 missing. **`cyrius deny`** — 57 deps, 0 violations.

## Deliberate deviation: `cyrius fmt`

`cyrius fmt --check` reports 12 of 40 authored files as non-canonical. **Every complaint is the same
thing**, verified file by file: an aligned continuation of a **trailing comment**, which the formatter
wants indented 2-or-4 spaces per open paren. Aligned trailing-comment continuations are a pervasive,
deliberate convention in this codebase and carry real readability weight.

Not reformatted. `cyrius fmt` is advisory in thoth (there is no CI step for it, matching `cyrlint`), and
rewriting 12 files to satisfy an advisory checker would create a large diff whose only effect is to destroy
a convention used on purpose. Recorded here so the next sweep does not re-litigate it.
