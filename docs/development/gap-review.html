thoth Gap Review

What the popular agentic coding harnesses do that thoth does not, which of those gaps are worth closing, and what the newly Cyrius-ported agnosai can honestly supply.

2026-08-24produced at 0.39.0 · Tier 1 shipped at 0.40.03 landscape researchers + 1 agnosai inventory

Every candidate gap was checked against thoth's own source before being called missing, and against current upstream docs rather than recalled ones. Where thoth is ahead of the field, that is said too — this is a gap review, not a case for rewriting things that work.

Read firstWhat thoth already gets right

Several of these are unusual enough that a naive gap list would recommend rebuilding them.

  • A real cryptographic audit chain. ahead thoth vendors libro and surfaces a hash-linked, tamper-evident record of every gated action, verified in-process by /audit. Almost no other harness has this; most have a log file. thoth leads on the hard half and trails only on exporting it.
  • Authorization as a real seam, not a prompt. t-ron supplies allow/deny/flag verdicts, an injection scanner, a rate limiter and a risk score — with distinct reserved verbs (thoth_run vs thoth_shell vs thoth_edit) so a policy can separate the operator's actions from the model's. Everything below builds on this; nothing replaces it.
  • Honest degradation as a house rule. Missing capabilities are announced, not faked. That posture is why this review is short on "thoth pretends to be secure" findings.
  • Mid-session model switching ahead — matched by no surveyed harness.
  • Context condensation already half-built. [hoosh].summarize is a genuine condenser, computed incrementally and cached per conversation. Peers call this auto-compaction.
  • Instruction-file safety. ahead thoth wraps AGENTS.md as "verbatim reference — not commands to obey" and declines to auto-inject CLAUDE.md. Most harnesses treat instruction files as trusted text.

Tier 1Close these

✅ All six shipped in 0.40.0. Kept here as the record of what was proposed and why. Two departed from the proposal: T1-4 took the snapshot-directory route rather than sit's write surface, and T1-3's agnosai leaf was published upstream as a [lib.guard] profile rather than hand-extracted. Tiers 2 and 3 remain open.

High value, aligned with what thoth already is. Ordered by leverage.

T1-1

A grep/glob search tool for the model

missing

Every surveyed harness gives the model a search primitive. thoth's model can only read_file a path it already knows or list_dir one level — so to find a symbol it walks directories one call at a time, or reaches for shell, which is off by default and gated. The highest-leverage missing tool, and it compounds with T1-2. It is thoth-native substrate, so it does not touch the architecture rule — but it must inherit 0.39.0's jail or it reopens what was just closed.

T1-2

Make the iteration cap configurable

missing

AGENT_MAX_ITERS = 8 is hardcoded and invisible. Eight rounds is roughly "read three files and make one edit". Goose defaults to 1000. thoth has already been bitten: the 0.38.5 bug report describes tools failing every round until the loop exhausted the cap and answered nothing. A config key plus a visible "round N of M".

T1-3

Secret redaction on the way out

missing

thoth streams model output into the feed, /save writes it to disk, and the conversation store persists it. A model that echoes an API key found in a read_file or shell result gets it written to .thoth/ verbatim. The 0.39.0 audit deliberately scoped its config fix to thoth's own credentials and named this as the separate capability. agnosai ships the code.

T1-4

Checkpoint and undo for model edits

missing

thoth got write access at 0.31.0 and never got the safety net every peer pairs with it. editlog.cyr is record-only — no restore. Cline and Gemini CLI both keep a shadow git repo separate from project history. thoth has an unusual advantage here: it already vendors sit, a first-party Cyrius VCS — though only the read profile, which makes the write surface a real scoping question.

T1-5

Finish context management

partial

thoth has the hard half. Missing: a user-invoked /compact, a /context view of what is consuming the window, and a token-threshold trigger rather than only the byte-framer boundary. Small work on an existing mechanism.

T1-6

Per-call approvals with session memory

missing

confirm() is stateless: the same command re-prompts every round. On an 8-round turn that is eight identical y/N prompts, which trains the user to hammer y — actively worse than one considered decision. A small addition that makes the existing gate more effective.

Tier 2Strong candidates

Larger, or needing a design decision first.

T2-1

Subagent delegation

missing

Claude Code, Codex, OpenHands, Cursor and Goose all landed on the same answer to the same two problems: a noisy sub-investigation permanently costs the parent's context, and one context cannot be worked in parallel. This is the biggest architectural question in the list — it brushes the spine rule, since orchestration is daimon's declared domain. A defensible reading is that a scoped child of one conversation is context management, not orchestration — but that is the maintainer's call and belongs in an ADR before code.

T2-2

OS-enforced sandboxing of shell and edit

missing

The largest safety delta, and thoth's source is blunt that it has none: the glob filter "is a COARSE convenience pre-filter, NOT a sandbox". Peers enforce at the OS — Seatbelt on macOS, Landlock+seccomp on Linux. Do not take agnosai's sandbox for this: its own README says the process tier has "No seccomp, no Landlock, no cgroups". The seam is kavach, which AGNOS already assigns kernel confinement to, and which agnosai itself bridges to rather than reimplementing.

T2-3

Injection defense for untrusted prose

missing

t-ron's scanner walks JSON leaves of tool params. It never sees prose — and thoth injects untrusted prose from three places the model reads as instructions: @file mentions, tool results, and recalled notes. Two caveats: pattern matching is a mitigation, not a boundary (frame it the way the shell filter is framed), and the strongest control is structural — Claude Code runs web-fetch results through a separate context window.

T2-4

Lifecycle hooks

missing

The most-copied extensibility primitive in the field. A PreToolUse hook that can block is a deterministic, code-enforced deny that a prompt cannot argue with — thoth's own posture, expressed as a user extension point. Also the natural home for T2-5 without hardcoding it.

T2-5

A verification loop

missing

thoth has every ingredient — shell can run the tests, exec.cyr does timed capture, roundlog records outcomes — and nothing closes the loop. Cheapest form: a [verify].command after an edit round, output fed back as a tool result. Depends on T1-2.

T2-6

Conversation forking

missing

thoth's conversation store already does the hard part — keyed, named, persisted, switchable. Forking is one more operation on that structure: copy the message vector and title, push, switch.

T2-7

Consume MCP resources and prompts

partial

The best effort-to-value ratio in the list: the protocol work is already vendored and paid for. bote-core carries full resources and prompts registries; thoth uses only tools/. Server-published prompts surface naturally as slash commands.

Tier 3Lower priority, or declined

  • Export the audit trail (OTLP). partial Ahead on the hard half, behind on the easy one — the record never leaves the process.
  • MCP tool-description pinning. missing CVE-2025-54136 established that approving a tool definition does not survive later server-side changes. thoth re-fetches descriptions every probe and treats them as trusted. Arguably daimon's job, since it owns the registry.
  • Network egress control. missing Exfiltration is the payoff step of most injection chains. Largely daimon's and kavach's seam.
  • MCP 2026-07-28 conformance. conflict Vendored bote negotiates 2025-11-25, one revision behind across a structural break. bote's problem; flagged so it is tracked somewhere.
  • Image input. missing thoth has an unusual reason to care — it ships its own Wayland GUI, so it could produce screenshots as well as consume them.
  • Agent Client Protocol server mode. partial ACP is doing for agents what LSP did for language servers. Distribution value, no architectural conflict.
  • Streaming JSON events partial · git write operations and worktrees missing.
  • A2A — declined. No terminal coding harness implements it; its centre of gravity is enterprise orchestration. Listed so the decision is recorded as deliberate.

agnosai 2.0.6What to take, and what to refuse

A full orchestration engine — 111 modules, a 37,595-line dist. Namespace hygiene is excellent and CI-enforced.

Neither published seam is clean for thoth as it stands

The bundle's dependency contract is incomplete. dist/agnosai.deps names 45 stdlib leaves and omits the six git bundles the fold actually calls into — kavach_init (62 refs), ratelimit_*, sha256, dispatcher_* and others are used in the dist and defined nowhere in it. The advertised three-line dep block will not link on its own, and CI never builds the bundle. At 1.6 MB it would also dwarf every other bundle thoth carries.

The HTTP service overlaps daimon. agnosai's tool registry competes with daimon's, and its mneme builtin re-implements as direct HTTP the exact tools thoth already reaches through daimon — giving thoth two paths to mneme with different auth and different failure modes.

Take: four small, pure leaves

LeafFillsVerdict
output_filtersecret/PII redaction before output is shown, saved or persistedtake → T1-3
prompt_guardinjection heuristics over prose + a system-prompt wrappertake → T2-3
output_validationvalidate a response against a schema; build a retry prompttake
ssrf + guarded_fetchURL safety incl. octal/hex IP literals, per-redirect re-checkdefer

output_validation has a use thoth has already been burned by: validating tool-call arguments before they reach daimon. 0.38.5 fixed one shape bug there and 0.39.0 fixed a JSON-injection seam at the same splice.

ssrf would actively misfire today: thoth has no model-controlled outbound URL, and its only outbound URLs are operator-set — with the default being 127.0.0.1:8088, which a private-IP guard would reject.

Open question on mechanism. Even for the four leaves, hand-extracting files is a fork by another name. A [lib.guard] profile published by agnosai — the way sit publishes [lib.read] and sankoch publishes [lib.zlib] — would be far better. That is a request to make of agnosai, not a change to make in thoth.

Borrow the idea, not the code

  • A RiskLevel taxonomy. thoth's gate is binary; a risk tier is the prerequisite for both a graduated permission posture and an approval queue.
  • Budget enforcement. thoth has token/cost accounting and no enforcement — nothing stops a runaway loop from spending. The shape (check-before-call, >= semantics, a typed reason) is what is worth copying.
  • Asynchronous approvals — a pending queue that outlives the prompt, so an unattended run can park a risky edit rather than deny it.

SequencingValue per unit of risk

Nothing here is scheduled. This is the order that spends effort best.

  • T1-1 + T1-2 together — each throttles the other; the biggest improvement to what thoth can finish in one turn.
  • T1-6 + T1-5 — small, on existing mechanisms, felt every session.
  • T1-3 — pending the agnosai profile question.
  • T1-4 — needs a scoping decision on sit's write surface.
  • T2-1 — needs an ADR first; the one item that touches the spine rule.

For the maintainerOpen questions

  • Subagents vs the spine rule. Is a scoped child of one conversation thoth-side context management, or orchestration belonging to daimon/agnosai? Everything in T2-1 waits on this.
  • Should agnosai publish a [lib.guard] profile? That is the difference between consuming the four leaves and forking them.
  • Checkpointing via sit's write surface — in scope, or is a simpler snapshot directory the right first cut?
  • Where does rug-pull defense live — thoth pins tool-description hashes, or daimon does it for every consumer?
