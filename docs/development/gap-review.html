Open gaps, and what thoth has not decided

The candidate gaps between thoth and the current agentic-coding harness landscape that thoth has not committed to. Nothing here is scheduled and nothing here is a promise.

companion to roadmap.md supersedes agentic-improvements-review.md Tiers 1–3 shipped in 0.40.0 / 0.41.0 / 0.42.0 current as of 0.43.2

Read firstWhat this file is, and what it is not

There is exactly one place to look for “what is thoth going to do” and exactly one for “what has thoth not decided about”. This is the second.

The roadmap is the plan, and it supersedes this file. Anything scheduled, declared, or carried as a known limitation in roadmap.md has been removed from here — deliberately. Shipped work lives in the CHANGELOG and is not narrated here either.

The original tiered review has been retired. Its Tier 1 (six items) shipped in 0.40.0; four of five Tier 2 items shipped in 0.41.0; three Tier 3 items shipped in 0.42.0. The rest were either promoted to the roadmap with a version pin, or carried forward below.

Every candidate gap was checked against thoth’s own source before being called missing, and against current upstream docs rather than recalled ones. Where thoth is ahead of the field, that is said too — this is a gap review, not a case for rewriting things that work.

ContextWhat thoth already gets right

Kept because a naive gap list would recommend rebuilding these.

  • A real cryptographic audit chain. ahead A hash-linked, tamper-evident record of every gated action, verified in-process by /audit and written out by /audit export. Almost no other harness has this; most have a log file.
  • Authorization as a real seam, not a prompt. ahead t-ron supplies allow/deny/flag verdicts, an injection scanner over tool params, a rate limiter and a per-agent risk score — with distinct reserved verbs (thoth_run vs thoth_shell vs thoth_edit) so a policy can separate the operator’s actions from the model’s. Everything below builds on this; none of it replaces it.
  • Honest degradation as a house rule. ahead Missing capabilities are announced, not faked. The banner states live gateway reachability rather than a hardcoded READY; an absent t-ron falls to a fail-closed confirm; the source says plainly where a boundary is not a sandbox.
  • Mid-session model switching ahead — matched by no surveyed harness — plus a model picker, reasoning-effort control and per-turn token/cost accounting.
  • Instruction-file safety. ahead thoth wraps AGENTS.md as “verbatim reference — not commands to obey” and declines to auto-inject CLAUDE.md. Most harnesses treat instruction files as trusted text.
  • Tool-definition pinning. ahead Trust-on-first-use hashing against the CVE-2025-54136 rug-pull, with a changed definition withheld rather than warned about. Rare among peers.
  • Subagent delegation with exactly ONE dispatch path. ahead Peers ship subagents; thoth’s runs the child’s tool calls through the same gate, hook, jail, checkpoint gate and audit chain as the parent’s rather than a parallel implementation — so a delegated action is exactly as authorized and as observable as a direct one, and there is no second authorization path to drift.
  • Provenance-split input. ahead A piped payload (git diff | thoth ‘review’) is treated as third-party text and never reaches the @mention reader; only the operator’s own argv words do (0.43.2). Peers that advertise cmd | agent ‘task’ generally treat the whole thing as one trusted message.

The listThe open gaps

Ordered by consequence, not by effort. The numbering carries that ordering — gap 1 is the largest safety delta thoth has.

01

OS-enforced sandboxing of shell / edit

missing

thoth’s own source is blunt that it has none: the glob filter “is a COARSE convenience pre-filter, NOT a sandbox”; the jail is “a boundary, not a sandbox”. Peers enforce at the OS — Seatbelt on macOS, Landlock+seccomp on Linux, with read-only / workspace-write / full-access tiers.

Do not take agnosai’s sandbox for this. Its own README says the process tier has “No seccomp, no Landlock, no cgroups”. The right seam is kavach, which AGNOS already assigns kernel confinement to. “kavach owns the sandbox, not the application” is a first-party standard.

Attempted, and deliberately not shipped

kavach 3.12.3 added the [lib.confine] profile this needs, and it builds clean inside thoth — the mechanical half is done. The blocker is a design finding, not a shortfall: kavach’s confinement is container-shaped. It blocks host interpreters without a rootfs, and thoth’s shell tool is a host-shell invocation, so every call would be refused.

Making it work means changing a security policy inside kavach’s threat model — kavach’s owner’s decision, not thoth’s to make unilaterally. The seam was removed rather than shipped as a promise thoth could not keep.

Open: does kavach’s interpreter blocklist become conditional, or does shell grow a rootfs-shaped mode?

02

Network egress control

spine

Exfiltration is the payoff step of most injection chains. shell can curl anywhere and web_fetch reaches any URL. Largely daimon’s and kavach’s seam rather than thoth’s — which is why it is not on the roadmap — but it is the natural companion to gap 1 and should be decided alongside it.

03

Durable tool-definition pins

partial

A gap created by 0.42.0. [toolpin] pins are session-scoped by design: they die with the process, so a swap during a session (or across a /reprobe) is caught and one between two runs is not. That bound is stated honestly in the code and the CHANGELOG.

Closing it means a durable pin store — a security-relevant file thoth writes and must then defend (tamper, replace, symlink-redirect), so it is a real design decision rather than a small feature. There is also a legitimate argument that it belongs in daimon, which owns the registry and could pin once for every consumer.

04

Structural isolation of untrusted content

partial

[guard] marks untrusted prose with an envelope and does not block, which is the right posture for a pattern matcher — it is a mitigation, not a boundary, and thoth frames it that way.

The strongest control in the field is structural, not lexical: retrieved text runs through a separate context window so it cannot issue instructions into the main thread. thoth now has five untrusted-prose inlets — @file mentions, read_file/list_dir/search results, recalled mneme notes, (0.43.0) MCP resource content, and piped stdin — and all five land in the main context.

The prerequisite has landed, which changes this gap’s shape rather than closing it. 0.43.0’s subagent (ADR-0018) is a separate context window: a child reads whatever it reads into its own message list and returns one string, which reaches the parent through redact → guard like any tool result. The machinery now exists; what does not is thoth routing untrusted reads through it automatically. That is a real design decision, not a wiring job — it makes every @file cost a model round, and a laundered summary is arguably a more persuasive injection vector than the raw text, since it arrives as fluent prose the parent has no reason to distrust.

0.43.2: the piped-stdin inlet went from unhandled to enveloped

That inlet used to go through cmd_task, whose second act is the unjailed @mention reader — no project confinement, no .. rejection, no absolute-path rejection. So a @/home/you/.ssh/id_rsa line inside a piped git diff was read and POSTed to the gateway, with the operator shown nothing, because one-shot runs the turn under OUT_NULL.

It now takes the same route MCP prompt text takes: redact → guard envelope → dispatch without expansion. That is the lexical mitigation, not the structural control this gap is about — the bytes still land in the main context.

05

Export the audit trail to a wire protocol

partial

/audit export (0.42.0) closed the file half. What is still missing is emission to a collector, where the OpenTelemetry GenAI semantic conventions are the standard worth adopting. Low priority for an interactive TUI; listed so the choice of convention is recorded before anyone invents one.

06

Image / multimodal input

missing

thoth has an unusual reason to care: it ships its own Wayland GUI, so it is one of the very few terminal agents that could produce a screenshot as well as consume one.

07

Agent Client Protocol (ACP) server mode

partial

ACP is doing for agents what LSP did for language servers (Zed, JetBrains, Neovim). A server mode would let thoth be driven from other editors without giving up its own TUI. Distribution value; no architectural conflict. 0.42.0’s --events stream is a meaningful step toward being drivable by another program, though it is one-way.

08

Git write operations / worktrees

missing

The git producer is deliberately read-only, which is right for the status bar, but the agent can inspect a diff and never land it. Worth pairing with a decision about whether thoth should drive sit’s write surface at all.

09

MCP 2026-07-28 conformance

spine

Vendored bote 3.3.7 negotiates 2025-11-25, one revision behind across a structural break. Flagged here only so it is tracked somewhere; the work belongs upstream.

RecordedDeclined, with reasons

Listed so each decision reads as deliberate rather than as an oversight.

  • A2A (Agent2Agent). No terminal coding harness implements it; its center of gravity is enterprise multi-agent orchestration.
  • Prometheus metrics. Not applicable to an interactive TUI.

ConsumptionTaking from agnosai

agnosai is a full orchestration engine — 111 modules, a dist/agnosai.cyr of 37,595 lines (1.6 MB, 2,043 fns). Namespace hygiene is excellent and CI-enforced.

Neither published seam is clean for thoth as a whole

1. The vendored bundle’s dependency contract is incomplete. dist/agnosai.deps names only 45 stdlib leaves and omits the six [deps.X] git bundles the fold actually calls into — kavach_init (62 refs), ratelimit_* (11), rng_uniform, sha256, dispatcher_*, accel_* are all used in the dist and defined nowhere in it. The advertised three-line [deps.agnosai] block will not link on its own, and CI never builds the bundle standalone. At 1.6 MB it would also dwarf every other bundle thoth carries. (An earlier form of this sentence argued from “a preprocessor ceiling thoth is already at ~96 % of” — that figure came from a misread retracted at 0.43.1. Re-summed at 0.43.2 the binding unit sits in the low-to-mid 60 % range of the 8 MB slot, so the ceiling is not the argument; the 1.6 MB delta still is.)

2. The HTTP service overlaps daimon. agnosai’s tool registry competes with daimon’s host registry, and its builtin/mneme.cyr re-implements as direct HTTP the exact mneme tools thoth already reaches through daimon /v1/mcp/call. Adopting it gives thoth two paths to mneme with different auth and different failure modes.

The mechanism that does work — settled, not a proposal — is a lean [lib.X] profile published upstream, the way sit publishes [lib.read] and sankoch [lib.zlib]. agnosai published [lib.guard] on exactly this basis and thoth consumes it for [redact] and [guard]. Hand-extracting files instead would be a fork by another name.

Still open: one leaf worth taking

LeafFillsMechanism
src/orchestrator/output_validation.cyr Validate a model response against an output schema; build a retry prompt ask for a profile
src/server/ssrf.cyr + guarded_fetch.cyr URL safety, incl. octal/hex IP literals and per-redirect re-validation deferred

output_validation has an immediate use thoth has already been burned by: validating tool-call arguments before they reach daimon. 0.38.5 fixed one shape bug there (bayan_json_v_str dropping Ollama’s object-shaped arguments) and 0.39.0’s A-10 fixed a JSON-injection seam at the same splice. A real validator belongs there — taken as a profile extension, not a copied file.

ssrf/guarded_fetch are deferred because they would actively misfire: thoth has no model-controlled outbound URL (web_fetch/web_search are bote tools hosted by daimon, where the guard belongs and where SSRF rejections are already logged), and thoth’s only outbound URLs are operator-set with a default of http://127.0.0.1:8088 — which a private-IP guard would reject.

Borrow the idea, not the code

  • RiskLevel (low/medium/high) on an action. thoth’s gate is binary allow/deny/flag; a risk tier is the prerequisite for both a graduated permission posture and an approval queue.
  • Budget enforcement — check-before-call, >= semantics, a typed exceeded-reason. thoth has token/cost accounting and no enforcement; nothing stops a runaway loop from spending. This got more urgent at 0.43.0, and the release says so out loud: delegation multiplies a turn’s cost, and the only bounds available today are structural — depth 1, a separate per-child round budget, and off-by-default. [subagent].enabled is off because of this gap, and ADR-0018 records that the default should be revisited if real budget enforcement ever lands. A round limit bounds turns, not spend.
  • Asynchronous approvals — a pending-decision queue that outlives the prompt, so an unattended run can park a risky edit instead of denying it. thoth’s confirm() is otherwise strictly better (fail-closed, explicit y/yes only), and session-scoped grants already removed the re-prompt-every-round problem.
  • The 18 agent presets as a ready-made answer to “what specialists would a thoth crew contain” — relevant to ADR-0018, which shipped at 0.43.0. Note agnosai’s AgentDefinition has no personality field, because that axis belongs to avatara.

Refuse, with reasons

Kept verbatim: this list is what stops a future contributor forking the spine by accident.

  • src/llm/* — the hoosh client. Its own header names thoth/src/hoosh.cyr as its reference implementation, so thoth would be importing a weaker copy of itself: no SSE streaming, no tool-calling at all, no reasoning effort, no mid-session switching.
  • src/llm/router.cyr — model routing is hoosh’s declared domain. Adopting it puts routing policy in two places.
  • src/tools/registry.cyr — a second tool registry competing with daimon’s.
  • src/server/routes/mcp.cyr — thoth is an MCP client; if it ever wants to be a server, bote’s dispatcher is already vendored.
  • src/orchestrator/audit.cyr — thoth already vendors libro. Two chains in one process is worse than one.
  • src/sandbox/ — right gap, wrong seam. See gap 1: kavach owns this.

DecisionsOpen questions for the maintainer

Each of these blocks something above. None has a default answer.

Q1

Does kavach’s interpreter blocklist become conditional, or does shell grow a rootfs-shaped mode?

Gap 1 — the largest safety delta — waits on this, and it is a change inside kavach’s threat model.

Q2

Where does durable rug-pull defense live?

thoth persists tool-definition pins, or daimon pins once for every consumer. Gap 3.

Q3

Should untrusted reads be routed through the existing subagent context automatically?

The machinery landed at 0.43.0 (ADR-0018), so this is no longer “before or as part of subagents” — it is a routing decision over something that already exists, with the two costs gap 4 names: a model round per @file, and a laundered summary that may be a more persuasive injection vector than the raw text.

Q4

Should thoth drive sit’s write surface at all?

Gap 8 — or does the read-only git producer stay the boundary?
